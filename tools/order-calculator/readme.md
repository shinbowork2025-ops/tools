# 発注数計算 v2(試作版)

定期発注方式(R,S)ベースの推奨発注数を手入力で計算し、「マザー発注数 / 新方式推奨数 / 自分の最終判断 / 実績」を端末内(IndexedDB)に記録して後から精度比較(ミニFVA)できるツールです。

- 所属企業の公式ツールではありません。実際の発注は社内システムと自身の判断で行ってください。
- 粗利率は名目値(既定30%)であり、実際の部門別粗利率は一切使いません(入力もさせず、保存もしません)。
- 外部への通信は行いません。データはすべて端末内にのみ保存されます。

## 構成

- `js/calc.js`: 計算モジュール(純関数のみ。UI・保存から独立しており単体で移植可能)
- `js/db.js`: IndexedDB永続化層(DB名 `order-calculator`、settings / items / records の3ストア)
- `js/app.js`: 画面制御(計算 / 記録一覧 / 設定のタブ)
- `js/jan-camera-ui.js` / `js/jan-scanner.js`: JANカメラ読取(木材カット図の実装を流用。連続一致判定はJANスキャンメモの `scan-consensus.js` を共用)

## 計算の概要

保護期間 P = 発注間隔7日 + リードタイム21日 = 28日(4週)。設定変更時は日割りでスケールします。

1. 欠品補正: 補正後6週販売数 S6c = 今年6週販売数 ÷ 在庫有り日数 × 42。在庫有り日数が42日の70%未満は要確認、30%未満は補正せず参考値
2. 低回転分岐(優先): 判定用週販((S6c+前年6週)÷12、前年実績0なら S6c÷6)が0.5未満なら正規近似を使わず、基準在庫 max(最低陳列数, 入数) とのbase-stock比較で0か1発注単位
3. 前年比補正(縮小推定): r = (S6c + k) ÷ (前年6週販売数 + k)。疑似カウントk(既定5、設定で変更可・0で無効)で小カウント時の過剰反応を1へ縮小する。保護期間需要 Dp = 前年今後4週販売数 × r。rが警告範囲(既定0.4〜2.5)の外なら要確認
4. 臨界比: CR = 名目粗利率 ÷ (名目粗利率 + 過剰コスト率)、z = Φ⁻¹(CR)(Acklamの有理近似)。CR≤0.5は安全在庫0
5. 安全在庫: SS = z × σw × √4。σw = max(変動係数 × 週平均需要, √週平均需要)(カウント需要のポアソン下限)
6. 推奨発注数: Q = Dp + SS − 現在庫 − 発注残。CR>0.5は入数切り上げ、CR≤0.5は切り捨て。丸め後も在庫+発注残+Qが最低陳列数を下回る場合は不足分を切り上げ補充
7. 新商品モード: 類似商品の28日販売数リストのCR分位点(線形補間)と最低陳列数のmaxを入数で切り上げ

精度比較(ミニFVA)の新方式誤差は、記録時に保存した予測値(toolForecastNext4w)で採点します(後から設定kを変えても採点基準がずれないようにするため)。

検算ケースは `js/calc.js` のコメントと `scripts/test-order-calc.mjs` にあります(`npm run check` で実行)。

## 記録(ミニFVA)

- 「この判断を記録」でISO週キー付きのレコードを保存
- 記録一覧の「実績入力待ち」からその後4週の実績販売数を追記
- 実績が入ると、ナイーブ予測(前年今後4週)・マザー発注数(代理指標)・新方式予測の平均絶対誤差と勝率を表示
- 本格的な集計(MASE等)はエクスポートしたJSON/CSVで外部分析する前提

## 注意

エクスポートには販売実績等の業務データが含まれます。取り扱いに注意してください。
